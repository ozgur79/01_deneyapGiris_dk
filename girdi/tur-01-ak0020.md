## 3. En kritik fark — `digitalWrite` burada YENİ

Portalın Ders 1.1'i dahili RGB LED'i şöyle yakıyor:

```cpp
void setup() { pinMode(LED_BUILTIN, OUTPUT); }
void loop() {
  neopixelWrite(RGBLED, 0, 0, 40);
  delay(1000);
  neopixelWrite(RGBLED, 0, 0, 0);
  delay(1000);
}
```

Yani öğrenci `setup`/`loop`, `pinMode`, `delay` gördü ama **`digitalWrite`'ı hiç görmedi** —
eylem `neopixelWrite`'tı.

ak0020'nin `ders.md`'si ise `digitalWrite`'ı **bilinen** sayıyor, çünkü Arduino tarafında
ak0010'da öğretilmişti. **Bu varsayım Deneyap'ta geçersiz.**

- `digitalWrite` bu derste **yeni kavram** olarak, kendi açıklamasıyla öğretilecek.
- `pinMode` Ders 1.1'de geçti, bilinen sayılır — ama sıra kilidi yok, ders kendi başına
  ayakta durmalı: tek cümlelik hatırlatma yeterli, sıfırdan anlatma.
- İstersen `neopixelWrite` ile `digitalWrite` arasındaki farka bir cümle ayır (biri renkli
  RGB LED'e üç kanal gönderir, öteki bir pini açıp kapatır) — öğrenci ikisini yan yana
  görmüş olacak, bağ kurmak ucuz.

**Önkoşul (Özgür'de):** ak havuzundaki `cpp.pinmode-digitalwrite` id'si ikiye bölünecek →
`cpp.pinmode` + `cpp.digitalwrite` (ak'nin `backlog.md`'sinde kayıtlı). Sen bölünmüş
varsayarak kullan. Havuzda hâlâ birleşik duruyorsa **id uydurma**, `backlog.md`'ne not düş.

## 5. `const int` KULLANMA

Portalın mevcut 1.2 taslağı `const int LED_PIN = 5;` kullanıyor. **Kullanma.**

Sebep: pine isim vermek ak'de ayrı bir ders (`ak0050`) ve arada `ak0030` ile `ak0040` var.
`ak0020` + `ak0050` birleştirmek paketleme değil **atlama** — ardışıklık kuralına aykırı.
`const int` Deneyap'a `ak0050` üretilince gelir; o zaman bu ders güncellenir ya da kavram
sonraki bir derse girer.

Pin numarası düz sayı olarak yazılır.

## 6. Kara kutu — üç katman

2. **Her kutu için ayrı Sokratik prompt** — §8'in kara kutu grubuna. `void` için ayrı,
